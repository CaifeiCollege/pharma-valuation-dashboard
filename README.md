# 医药估值温度计

一个可公开转发、自动更新的医药行业估值看板。页面展示整体法 PE-TTM、最近十年日频百分位和历史走势，适配手机与电脑。

## 看板包含什么

- 医药行业：中证医药、中证全指医药
- 创新药：SHS创新药、中证创新药
- CXO
- 医疗器械
- 医疗服务及中证医疗参考项
- 生物疫苗及国证疫苗生物参考项
- 中药
- 医药商业

估值统一采用与支付宝展示方式交叉核对过的整体法 PE-TTM。百分位计算为：最近十年有效日频 PE 中，小于或等于当前 PE 的样本占比；成立不足十年的指数按成立以来计算。

申万医疗服务与申万医药商业采用申万宏源研究公开的整体法PE历史。该序列已使用保险Ⅱ、券商Ⅱ、非银金融三个重合指数与FundDB逐日交叉核对，重合交易日数值完全一致。

CXO与中证疫苗生物目前没有公开可得的同口径历史数据，页面会明确显示“数据暂缺”，不会把中证官网的普通PE或相近指数冒充为支付宝整体法PE-TTM。

## 第一次发布到 GitHub Pages

1. 在 GitHub 新建一个公开仓库，例如 `pharma-valuation-dashboard`。
2. 把本项目中的全部文件上传到仓库根目录，默认分支保持为 `main`。
3. 打开仓库的 `Settings → Pages`。
4. 在 `Build and deployment` 的 `Source` 中选择 `GitHub Actions`。
5. 打开仓库的 `Actions` 页，选择“更新医药估值并发布”，点击 `Run workflow`。
6. 首次运行成功后，Pages 页面会显示公开网址。以后别人打开同一网址即可看到最近一次自动更新的数据。

公开网址通常是：`https://你的用户名.github.io/pharma-valuation-dashboard/`

## 自动更新时间

工作流在每个工作日北京时间 18:30 自动运行，也支持在 Actions 页面手动运行。它会先测试，再更新数据，最后发布网页。

为减少无意义的失败邮件，更新器对每个指数独立处理：

- 某一个接口失败：该指数沿用上次成功值，并标记“沿用旧值”。
- 全部上游接口暂时失败：只要仓库里仍有有效快照，任务继续成功发布旧数据。
- 只有新旧数据都不可用、数据文件损坏或程序本身出错时，任务才会真正失败。
- 每次运行摘要都会列出 `current`、`stale`、`unavailable` 数量，方便直接判断是哪种情况。

## 本地查看

在项目目录运行：

```text
python -m http.server 8000
```

然后打开 `http://127.0.0.1:8000/`。不要直接双击 HTML 文件，因为浏览器可能阻止它读取本地 JSON。

## 手动更新与检查

安装依赖并更新：

```text
python -m pip install -r requirements.txt
python scripts/update_data.py --output data/valuations.json --fallback data/valuations.last-good.json
```

运行全部检查：

```text
python -m unittest discover -s tests -v
```

## 收到失败邮件时怎么看

进入仓库 `Actions`，打开失败的那一次运行：

1. 先看“输出可读诊断摘要”。正常情况会显示当前值、沿用值和暂缺值的数量。
2. 如果只是一两个指数接口中断，任务按设计不应失败，而是沿用旧值。
3. 若失败发生在安装依赖或发布步骤，通常属于 GitHub 网络或 Pages 服务问题，可点击 `Re-run jobs` 重试。
4. 若失败发生在数据校验，旧快照也可能已损坏；可从仓库历史恢复最近一次有效的两个 JSON 文件后手动重跑。

## 文件说明

- `index.html`、`assets/`：公开网页
- `data/valuations.json`：网页使用的当前快照
- `data/valuations.last-good.json`：自动更新失败时的恢复快照
- `scripts/`：数据获取、计算、校验和安全写入
- `tests/`：签名、百分位、容错及网页契约检查
- `.github/workflows/`：定时更新和 GitHub Pages 发布
